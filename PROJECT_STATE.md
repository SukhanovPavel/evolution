## Что реализовано

Полноценное русскоязычное приложение на Next.js App Router, React и strict TypeScript. Стили — CSS Modules, без Tailwind. Supabase Auth, PostgreSQL, Storage и RLS; versioned REST `/api/v1/*`, TanStack Query, RHF/Zod, небольшой UI store Zustand.

- Landing, регистрация/вход/выход, подтверждение и восстановление пароля, SSR cookies, проверка пользователя в API.
- Onboarding и настройки профиля: цели, питание, аллергии, ограничения, бюджет времени, оборудование, часовой пояс.
- Три 30-дневные программы, 24 рецепта, 30 упражнений, 8 комплексов. Оригинальные русские seed-данные.
- Сегодня: генерация персонального плана, выполнение/пропуск, check-in, объяснение адаптации. Повторные запросы не создают дубликаты. Боль/болезнь/усталость не увеличивают нагрузку; пропущенные задачи не накапливаются.
- Питание, избранное, список покупок; комплексы с техникой, таймером и паузой; прогресс по сохранённым записям; детерминированный coach.
- Защищённый admin CRUD, экспорт своих данных, путь удаления аккаунта (ограничение по ключу ниже).
- PWA: manifest, иконки, service worker и offline fallback. Приватный HTML/API/health-данные не кэшируются. Это не полноценное offline-приложение.
- Архитектура будущего Capacitor: domain/contracts и API transport отделены, API принимает проверяемые bearer tokens; SSR остаётся на Vercel. Native app, CORS/deep links и безопасное native-хранилище ещё не включены.

## Последние изменения по запросу владельца

### Письмо подтверждения уводило на localhost

В приложении закреплён `NEXT_PUBLIC_APP_URL=https://evolution-azure.vercel.app`. Signup, resend и password recovery формируют callback через `src/lib/app-origin.ts`; callback после обмена кода также использует этот origin. Добавлена кнопка повторной отправки подтверждения. Production-сборка Vercel проверяет наличие HTTPS APP_URL.

**Облачная настройка Supabase Auth ещё требует действия владельца.** Владелец ответил: «настройку авторизации сделаю позже и проверю». Не утверждать, что доставка настоящего письма и редирект уже проверены. Доступ к PostgreSQL не даёт возможности изменить управляемую конфигурацию Auth; Management PAT отсутствовал.

Supabase → Authentication → URL Configuration:

- Site URL: `https://evolution-azure.vercel.app`
- Redirect URLs: `https://evolution-azure.vercel.app/auth/callback`
- И `https://evolution-azure.vercel.app/auth/callback?next=/reset-password`

После изменения запросить новое письмо; адрес в уже отправленном письме не переписывается. PKCE-письмо открывать в том браузере, где начат процесс.

### Web Push

В Настройки → Уведомления есть разрешение на текущем устройстве, тестовый push, отключение устройства и сохранение расписания. Питание — один раз в выбранное время; разминка — каждые 30/60/90/120 минут в рабочие часы, опционально только будни. Часовой пояс берётся из профиля. При недавней боли/болезни или ограничениях вместо разминки — спокойный отдых.

Миграция `202610140006_web_push.sql` применена к Supabase. Таблицы `push_settings`, `push_subscriptions` защищены RLS. Закрытая схема `evolution_private` содержит hash worker-секрета и delivery leases. Узкие RPC проверяют отдельный секрет; service-role key для worker не требуется. Проверяются допустимые push endpoints; есть дедупликация, до трёх попыток, удаление истёкших подписок при 404/410, 15-минутное окно актуальности.

Supabase Cron `evolution-push` активен с `*/5 * * * *`, вызывает POST `/api/v1/notifications/dispatch` через pg_net. Секрет находится в Vault, приватные VAPID и worker key — в Vercel Production. Постоянный серверный процесс и частый Vercel Cron не нужны. При выходе из аккаунта подписка текущего устройства отключается.

На последней проверке worker отвечал HTTP 200 `{processed:0,sent:0}`: инфраструктура доступна, **владелец 15 октября подтвердил успешное получение push на физическом устройстве**. Для ручной проверки разрешить push в настройках и отправить тест. На iPhone/iPad: iOS 16.4+, сначала установить PWA на главный экран и открыть установленное приложение.

### Современный стиль

Причина «жирных рамок» — ошибочный глобальный CSS-селектор: `:focus-visible` применялся только к последнему элементу списка, остальные постоянно получали outline. Исправлены все селекторы; контур виден только при keyboard focus. У карточек убрана граница, добавлена мягкая тень, у полей тонкие границы. Доступность фокуса сохранена и проверена браузерными тестами.

## Секреты и миграции

- `.env.local` приватный, игнорируется Git и Vercel upload. Не читать значения в вывод инструментов/чат, не копировать в документацию. Примеры переменных — в `.env.example`.
- `SUPABASE_DB_URL` — Session pooler PostgreSQL URI; использовался для миграций через psql. Прямой IPv6-host был недоступен. DB password не нужен Vercel runtime и был удалён из окружений Vercel.
- Локально имеются VAPID pair и worker secret; не генерировать заново без причины. Смена VAPID pair потребует переподключения устройств.
- `SUPABASE_SERVICE_ROLE_KEY` и `SUPABASE_ACCESS_TOKEN` на последней проверке отсутствовали. Удаление Auth-аккаунта без server key возвращает `503 ACCOUNT_DELETION_NOT_CONFIGURED`.
- Применены миграции 001–007 и seed. Мигратор хранит историю и checksums; **не редактировать применённые миграции**, добавлять следующую. `deployment_readiness()` пока сообщает версию базовой схемы 5 — это не означает, что миграция 006 не применена.
- `supabase/bootstrap.sql` генерируется через `npm run db:prepare`; не редактировать вручную. `tests/postgres-bootstrap.sql` — только заглушки для временной локальной БД, не применять к Supabase.
- `scripts/setup-push.mjs --generate` сохраняет/создаёт ключи в `.env.local`; обычный запуск настраивает Vault/Cron. Это административные операции, не выполнять заново при обычном запуске приложения.
- `scripts/push-vercel-env.mjs` загружает только четыре разрешённые push/APP_URL переменные в production-проект владельца. Не использовать автоматически для другого аккаунта/окружения.

```sh
npm run dev

npm run test:demo
npm run supabase:status
npm run test:cloud:rls
EVOLUTION_TEST_BASE_URL=https://evolution-azure.vercel.app npx playwright test tests/e2e/smoke.spec.ts
```

Сначала завершать production build, затем запускать E2E: одновременная пересборка `.next` мешает старту тестового сервера. Для миграций после добавления новой версии: `npm run db:prepare`, затем `npm run db:migrate` с административным доступом. Проверять назначение базы перед запуском SQL-скриптов.

- `src/app/` — страницы, auth callback, Route Handlers; `src/server/api.ts` — основной API dispatcher.
- `src/domain/` — схемы, контент, даты, адаптация и прогресс; `src/i18n/ru.ts` — русские строки.
- `src/components/Notifications.tsx`, `src/server/push.ts`, `src/app/api/v1/notifications/dispatch/route.ts` — push UI и worker.
- `src/lib/` — Supabase, HTTP transport, repository, demo, app origin.
- `public/sw.js` — offline fallback, получение push и обработка клика.
- `supabase/migrations/`, `supabase/seed.sql` — БД; `scripts/`, `tests/` — проверки и настройка.
- `README.md` — развёртывание и архитектура; `VERIFICATION.md` — журнал проверок.
